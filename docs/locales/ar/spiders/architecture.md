# بنية العناكب {#spiders-architecture}

!!! success "قبل البدء"

    1. اقرأ صفحة [أساسيات أدوات الجلب](../fetching/choosing.md) لفهم أنواع أدوات الجلب المختلفة ومتى تستخدم كل نوع.
    2. اقرأ صفحة [الكلاسات الأساسية](../parsing/main_classes.md) لفهم كلاس [Selector](../parsing/main_classes.md#selector) وكلاس [Response](../fetching/choosing.md#response-object).

نظام العناكب في Scrapling هو إطار زحف غير متزامن مستوحى من Scrapy. صُمّم لتشغيل طلبات متزامنة وجلسات متعددة، مع دعم مدمج للإيقاف المؤقت والاستكمال. يجمع بين محرك التحليل وأدوات الجلب في Scrapling ضمن API واحد للزحف، ويضيف جدولة الطلبات والتحكم في التزامن وحفظ نقاط الاستكمال.

إذا سبق لك استخدام Scrapy، فستجد طريقة العمل مألوفة. وإذا لم تستخدمه من قبل، فلا تقلق، فالنظام مصمّم ليكون سهل الاستخدام.

## مسار البيانات {#data-flow}

هذه هي الخطوات الأساسية عند تشغيل العنكبوت، دون الدخول في تفاصيل كثيرة:

1. ينشئ **العنكبوت** المجموعة الأولى من كائنات `Request`. افتراضيًا، ينشئ طلبًا لكل URL في `start_urls`، ويمكنك إعادة تعريف `start_requests()` لتخصيص هذه الخطوة.
2. يستقبل **Scheduler** الطلبات ويضعها في طابور حسب الأولوية، وينشئ بصمة لكل طلب. تخرج الطلبات الأعلى أولوية أولًا.
3. يطلب **محرك الزحف** من **Scheduler** إخراج الطلب التالي، مع الالتزام بحدود التزامن العامة ولكل نطاق، وفترات الانتظار بين الطلبات. إذا كان `robots_txt_obey` مفعّلًا، يفحص المحرك قواعد robots.txt للنطاق قبل المتابعة، ويتجاهل الطلبات غير المسموح بها دون رسالة. ثم يرسل الطلب إلى **مدير الجلسات** الذي يختار الجلسة المناسبة وفقًا لقيمة `sid`، أي معرّف الجلسة، في الطلب.
4. تجلب **الجلسة** الصفحة وتعيد كائن [Response](../fetching/choosing.md#response-object) إلى **محرك الزحف**. يسجّل المحرك الإحصاءات ويفحص الرد لمعرفة ما إذا كان الموقع قد حظر الطلب. عند الحظر، يعيد المحاولة حتى `max_blocked_retries` مرة. يمكنك تخصيص طريقة اكتشاف الحظر وطريقة إعادة المحاولة.
5. يمرّر **محرك الزحف** كائن [Response](../fetching/choosing.md#response-object) إلى دالة callback الخاصة بالطلب. تُخرج هذه الدالة إما قاموسًا يُعامل كعنصر بيانات مستخرج، أو طلب متابعة يُرسل إلى Scheduler لإضافته إلى الطابور.
6. تتكرر الدورة من الخطوة 2 حتى يفرغ الطابور ولا تبقى مهام تعمل، أو حتى يتوقف العنكبوت مؤقتًا.
7. إذا ضبطت `crawldir` عند تشغيل العنكبوت، يحفظ **محرك الزحف** نقطة استكمال على القرص بصورة دورية. تشمل الطلبات المعلّقة ومجموعة عناوين URL التي سبق رصدها. عند الإغلاق المنظم باستخدام Ctrl+C، يحفظ نقطة أخيرة. وعند تشغيل العنكبوت مجددًا بقيمة `crawldir` نفسها، يستكمل من حيث توقف، دون تشغيل `start_requests()`، مع استعادة حالة الطابور.

## المكونات {#components}

### Spider {#spider}

الكلاس الأساسي الذي تتعامل معه. أنشئ كلاسًا يرث من `Spider`، وحدد `start_urls` ودالة `parse()`. ويمكنك أيضًا إعداد الجلسات وإعادة تعريف دوال مراحل التشغيل.

```python
from scrapling.spiders import Spider, Response, Request

class MySpider(Spider):
    name = "my_spider"
    start_urls = ["https://example.com"]

    async def parse(self, response: Response):
        for link in response.css("a::attr(href)").getall():
            yield response.follow(link, callback=self.parse_page)

    async def parse_page(self, response: Response):
        yield {"title": response.css("h1::text").get("")}
```

### محرك الزحف {#crawler-engine}

يدير المحرك عملية الزحف كلها. يشغّل الحلقة الأساسية، ويطبّق حدود التزامن، ويرسل الطلبات عبر مدير الجلسات، ويعالج النتائج التي تعيدها دوال callback. لا تحتاج إلى التعامل معه مباشرة، لأن `Spider.start()` و`Spider.stream()` يقومان بذلك.

### Scheduler {#scheduler}

طابور يرتّب الطلبات حسب الأولوية، مع منع التكرار تلقائيًا. تُحسب بصمة الطلب من عنوان URL وطريقة HTTP ومحتوى الطلب ومعرّف الجلسة. يدعم Scheduler الدالتين `snapshot()` و`restore()` لحفظ حالة الزحف واستعادتها من نقاط الاستكمال.

### مدير الجلسات {#session-manager}

يدير جلسة واحدة أو أكثر، لكل منها اسم. تكون كل جلسة من أحد النوعين:

- [FetcherSession](../fetching/static.md)
- [AsyncStealthySession](../fetching/stealthy.md)

عند وصول طلب، يختار مدير الجلسات الجلسة المناسبة حسب حقل `sid`. يمكن تشغيل الجلسات مع بداية العنكبوت، وهذا هو السلوك الافتراضي، أو عند أول استخدام لها فقط.

### نظام نقاط الاستكمال {#checkpoint-system}

نظام اختياري يحفظ حالة الزاحف، أي الطلبات المعلّقة وبصمات عناوين URL التي سبق رصدها، في ملف pickle على القرص. تتم الكتابة بإنشاء ملف مؤقت ثم إعادة تسميته، لتجنب تلف الملف. تُحفظ النقاط دوريًا بفاصل قابل للضبط، وعند الإغلاق المنظم. بعد اكتمال الزحف بنجاح دون إيقاف مؤقت، تُحذف ملفات نقاط الاستكمال تلقائيًا.

### ذاكرة الردود المؤقتة {#response-cache}

ميزة اختيارية تحفظ كل رد على القرص عند تفعيل وضع التطوير، وتعيد استخدامه في مرات التشغيل التالية. يُحفظ كل رد تحت مفتاح هو بصمة الطلب، بصيغة JSON، مع ترميز المحتوى باستخدام base64 للحفاظ على المحتوى الثنائي. الغرض منها هو تعديل منطق `parse()` وتجربته دون تكرار الطلبات إلى خوادم الموقع، وليست مخصّصة للتشغيل الفعلي.

### النتائج {#output}

تُجمع البيانات المستخرجة في `ItemList`، وهي كلاس يرث من list ويتيح التصدير عبر `to_json()` و`to_jsonl()` و`to_csv()` و`to_xml()`. تُسجّل إحصاءات الزحف في dataclass اسمها `CrawlStats` وتحتوي على معلومات كثيرة مفيدة.

## مقارنة مع Scrapy {#comparison-with-scrapy}

إذا كنت تستخدم Scrapy، فهذه هي المكونات المقابلة في Scrapling:

| المفهوم | Scrapy | Scrapling |
|---------|--------|-----------|
| تعريف العنكبوت | كلاس يرث من `scrapy.Spider` | كلاس يرث من `scrapling.spiders.Spider` |
| الطلبات الأولى | `start_requests()` | `async start_requests()` |
| دوال callback | `def parse(self, response)` | `async def parse(self, response)` |
| متابعة الروابط | `response.follow(url)` | `response.follow(url)` |
| إخراج البيانات | `yield dict` أو `yield Item` | `yield dict` |
| جدولة الطلبات | Scheduler + Dupefilter | Scheduler مع منع التكرار مدمجًا |
| التنزيل | Downloader + Middlewares | مدير جلسات يدعم جلسات متعددة |
| معالجة البيانات | Item Pipelines | دالة `on_scraped_item()` |
| اكتشاف الحظر | عبر middlewares مخصّصة | الدالتان المدمجتان `is_blocked()` و`retry_blocked_request()` |
| التزامن | الإعداد `CONCURRENT_REQUESTS` | خاصية الكلاس `concurrent_requests` |
| تصفية النطاقات | `allowed_domains` | `allowed_domains` |
| Robots.txt | الإعداد `ROBOTSTXT_OBEY` | خاصية الكلاس `robots_txt_obey` |
| الإيقاف المؤقت والاستكمال | الإعداد `JOBDIR` | معامل إنشاء الكلاس `crawldir` |
| التصدير | Feed exports | `result.items.to_json()` / `to_jsonl()` / `to_csv()` / `to_xml()` أو تخصيصه عبر دوال مراحل التشغيل |
| التشغيل | `scrapy crawl spider_name` | `MySpider().start()` |
| استقبال البيانات أثناء الزحف | غير متاح | `async for item in spider.stream()` |
| جلسات متعددة | غير متاح | عدة جلسات بأنواع مختلفة في العنكبوت نفسه |
