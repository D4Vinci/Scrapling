# Переход на v0.5 {#migrating-to-v05}

В этом руководстве описаны изменения, которые нужно проверить при переходе с **v0.4.15 на v0.5**. Сюда входят удалённые API, переименованные инструменты и исправления, которые могут изменить результаты обхода или сохранённые файлы.

## Краткий список изменений {#quick-migration-checklist}

| Если вы используете... | Что изменить |
| --- | --- |
| `DynamicFetcher`, `DynamicSession` или `AsyncDynamicSession` | Используйте соответствующий класс со скрытным режимом. |
| `capture_xhr` или `response.captured_xhr` | Используйте браузерную сессию с `record_requests=True` и `session.network`. |
| `keep_cdata` | Удалите из настроек парсера и Fetcher. |
| `scrapling extract stealthy-fetch` или `stealthy_fetch()` в оболочке | Используйте `fetch` вместо них. |
| Инструменты MCP | Обновите имена инструментов, вызовы снимков экрана и обработку ответа при создании сессии. |
| `response.follow()` после POST-запроса или запроса с параметрами строки запроса | Передайте метод, параметры и тело заново, если они нужны. |
| Сохранённые контрольные точки обхода или кэши ответов | Начните новый обход, если ваши запросы используют изменившиеся входные данные отпечатка. |
| `robots_txt_obey=True` | Обрабатывайте ошибки загрузки robots.txt: теперь они блокируют обход этого домена. |

## Загрузка через браузер {#browser-fetching}

### Замените классы динамического браузера {#replace-the-dynamic-browser-classes}

Браузерный движок, который напрямую использовал Playwright, удалён. Теперь вся загрузка через браузер использует скрытный движок на основе Patchright.

| Удалённый API | Замена |
| --- | --- |
| `scrapling.DynamicFetcher` | `scrapling.StealthyFetcher` |
| `scrapling.fetchers.DynamicFetcher` | `scrapling.fetchers.StealthyFetcher` |
| `scrapling.fetchers.chrome.PlayWrightFetcher` | `scrapling.fetchers.StealthyFetcher` |
| `scrapling.fetchers.DynamicSession` | `scrapling.fetchers.StealthySession` |
| `scrapling.fetchers.AsyncDynamicSession` | `scrapling.fetchers.AsyncStealthySession` |

Модуль `scrapling.fetchers.chrome` и приватный модуль `_browsers._controllers` удалены. Используйте публичные импорты из таблицы выше.

**Раньше:**

```python
from scrapling.fetchers import DynamicFetcher

page = DynamicFetcher.fetch("https://example.com", headless=True)
```

**Теперь:**

```python
from scrapling.fetchers import StealthyFetcher

page = StealthyFetcher.fetch("https://example.com", headless=True)
```

Для сессий замените `DynamicSession` на `StealthySession`, а `AsyncDynamicSession` на `AsyncStealthySession`. Сделайте ту же замену в методе `configure_sessions()` вашего паука. Способы использования `fetch()` и `async with` остаются прежними.

Если ваши обработчики импортируют типы браузера или перехватывают его ошибки, замените `playwright.sync_api` на `patchright.sync_api` или `playwright.async_api` на `patchright.async_api`. Это относится к `Page`, `Locator`, `Error` и `TimeoutError`.

По умолчанию Patchright выполняет JavaScript в изолированном контексте. Если обработчик читает собственные JavaScript-переменные страницы, используйте `page.evaluate(..., isolated_context=False)`.

Меняется не только имя импорта, но и поведение браузера. Проверьте флаги браузера и настройки отпечатка. Для прохождения Cloudflare по-прежнему нужно `solve_cloudflare=True`; по умолчанию эта возможность отключена. Кроме того, `extra_flags` теперь дополняет встроенные флаги скрытного режима, а не заменяет их.

Текущие параметры описаны в разделе [Загрузка через браузер](fetching/stealthy.md).

### Замените захват XHR историей сетевых запросов сессии {#replace-xhr-capture-with-session-network-history}

Параметр `capture_xhr` и атрибут `Response.captured_xhr` удалены. Удалите параметр, даже если его значение равно `None`. Ответ разовой загрузки больше не содержит список XHR.

Пользовательские интеграции, вызывающие `ResponseFactory.from_playwright_response()` или `ResponseFactory.from_async_playwright_response()`, также должны удалить `xhr_captured`. Передавайте `collect_history` по имени, чтобы избежать проблем из-за нового порядка позиционных аргументов.

**Раньше:**

```python
from scrapling.fetchers import StealthyFetcher

page = StealthyFetcher.fetch("https://example.com", capture_xhr="/api/")
for response in page.captured_xhr:
    print(response.url, response.body)
```

**Теперь:**

```python
from scrapling.fetchers import StealthySession

with StealthySession(record_requests=True) as session:
    page = session.fetch("https://example.com", network_idle=True)
    for response in session.network.search(url_pattern=r"/api/", limit=None):
        print(response.url, response.body)
```

В асинхронном коде используйте `AsyncStealthySession` и `await session.fetch(...)`. Для чтения `session.network` не нужен `await`.

Есть несколько важных отличий:

- Задайте `record_requests=True` при создании сессии. Это настройка сессии, а не отдельной загрузки.
- История относится ко **всей сессии**, включая вкладки, загрузки страниц и действия. Используйте `after_id`, фильтры или `session.network.clear()`, если нужен более узкий охват.
- При поиске в истории перенесите прежнее регулярное выражение из `capture_xhr` в `url_pattern`.
- `search()` возвращает сохранённые объекты `Response`. Читайте `.url`, `.status`, `.headers`, `.body` или `.json()` напрямую. ID записи, тип ресурса и отправленное тело находятся в `response.meta["network_id"]`, `response.meta["resource_type"]` и `response.meta["request_body"]`.
- История в Python по умолчанию включает все типы ресурсов. Используйте `resource_type="xhr"` или `resource_type="fetch"`, чтобы выбрать один тип, либо `include_static=False` для запросов XHR/fetch вместе с ошибками HTTP.
- `search()` по умолчанию возвращает не более 100 совпадений. Передайте `limit=None`, чтобы получить все сохранённые совпадения. Сессии по умолчанию хранят не более 1 000 запросов; это можно изменить через `max_recorded_requests`.
- Сохраняются только завершённые запросы. Захват тела доступен только для поддерживаемых текстовых типов содержимого. Ограничения составляют 1 MiB на ответ и 20 MiB для всех сохранённых тел ответов. При достижении лимитов старые записи могут удаляться. Причину пропуска тела можно узнать через `response.meta.get("body_note")`.
- Чтение истории или закрытие сессии не ожидает завершения записи ответов. Дождитесь нужных данных, прежде чем читать их. Сохранённая история Python остаётся доступной после закрытия сессии.

Фильтры и ограничения описаны в разделе [История сетевых запросов](fetching/stealthy.md#network-history).

## Настройки парсера {#parser-settings}

### Удалите `keep_cdata` {#remove-keep_cdata}

`keep_cdata` удалён из `Selector`, конфигурации Fetcher и настроек, которые возвращает `display_config()`. Удалите его из прямых вызовов парсера, `Fetcher.configure(...)` и словарей `selector_config`, передаваемых в Fetcher или интеграции.

**Раньше:**

```python
from scrapling import Selector

page = Selector("<p>Hello</p>", keep_cdata=True)
```

**Теперь:**

```python
from scrapling import Selector

page = Selector("<p>Hello</p>")
```

Замены этой настройке нет. Она не влияла на результат HTML-парсера. Если вы передавали настройки парсера по позиции, удалите старый аргумент `keep_cdata` и передавайте `adaptive` и настройки хранения по имени.

## Командная строка и интерактивная оболочка {#command-line-and-interactive-shell}

### Используйте `fetch` для запросов через браузер {#use-fetch-for-browser-requests}

В CLI теперь одна браузерная команда: `scrapling extract fetch`. Она использует `StealthyFetcher`.

**Раньше:**

```bash
scrapling extract stealthy-fetch "https://example.com" page.md
```

**Теперь:**

```bash
scrapling extract fetch "https://example.com" page.md
```

Если вы уже используете `scrapling extract fetch`, имя команды не меняется, но её движок меняется с `DynamicFetcher` на `StealthyFetcher`. Такие параметры, как `--solve-cloudflare`, теперь относятся к `fetch`.

В `scrapling shell` замените `stealthy_fetch(...)` на `fetch(...)`. Существующий сокращённый вызов `fetch(...)` теперь вызывает `StealthyFetcher.fetch`. Динамические классы больше не добавляются в пространство имён оболочки.

### Читайте файлы Markdown и текстовые файлы как UTF-8 {#read-markdown-and-text-files-as-utf-8}

Команды извлечения и `Convertor.write_content_to_file()` теперь записывают файлы `.md` и `.txt` в **UTF-8**, независимо от кодировки исходной страницы. Обновите код, который читает эти файлы в исходной кодировке страницы. Вывод `.html` по-прежнему использует `page.encoding`.

Markdown из нескольких выбранных элементов теперь содержит пустые строки между элементами. Это относится к `Response.markdown()` и записи файлов Markdown. Обновите точные сравнения вывода или сохранённые хеши, которые зависели от текста, склеенного без разделителей.

## MCP-сервер {#mcp-server}

Обновите сохранённые промпты, списки разрешённых инструментов, обёртки и определения инструментов MCP-клиента. После обновления сервера перезапустите или переподключите MCP-клиент, чтобы он прочитал текущий список инструментов.

### Обновите имена инструментов и пакетные вызовы {#update-tool-names-and-bulk-calls}

| Инструмент в v0.4.15 | Замена в v0.5 |
| --- | --- |
| `fetch`, `stealthy_fetch` | `browser_fetch_once` |
| `open_session` | `browser_open` |
| `session_fetch` | `browser_fetch` |
| `screenshot` | `browser_screenshot` |
| `bulk_fetch`, `bulk_stealthy_fetch` | Один вызов `browser_fetch_once` на URL или повторные вызовы `browser_fetch` через открытую сессию |
| `bulk_get` | Один вызов `make_request` или `session_make_request` на URL |

Все пакетные инструменты удалены. Инструменты загрузки одного URL возвращают один `ResponseModel` с `status`, `content` и `url`, а не список ответов. Само поле `content` по-прежнему содержит список строк.

Все браузерные инструменты MCP теперь используют скрытный движок. Удалите `session_type` из вызовов `browser_open`; выбор динамического браузера больше недоступен. Результат содержит `session_type="stealthy"`. HTTP-сессии по-прежнему используют `open_request_session` и возвращают `session_type="static"`.

Интеграции Python также должны перестать импортировать удалённый `BrowserSessionType`. `SessionType` теперь принимает только `"stealthy"` и `"static"`.

Вызовы в одной браузерной сессии должны выполняться по порядку, так как они используют общую страницу. По завершении закрывайте сессии через `close_session`.

### Читайте настройки через `list_sessions` {#read-settings-through-list_sessions}

`browser_open` и `open_request_session` теперь возвращают только:

```json
{
  "session_id": "my-session",
  "session_type": "stealthy"
}
```

Результат создания больше не включает `created_at`, `is_alive`, `settings` или `message`. Вызовите `list_sessions`, чтобы получить первые три поля. Подтверждение `message` удалено. Код, который предполагал, что `SessionCreatedModel` содержит все поля `SessionInfo`, тоже нужно изменить.

### Загрузите страницу перед снимком экрана {#fetch-before-taking-a-screenshot}

`browser_screenshot` снимает **текущую страницу без повторной загрузки**. Инструмент больше не принимает URL и прежние параметры перехода и ожидания: `wait`, `wait_selector`, `wait_selector_state` и `network_idle`.

Используйте такой порядок:

1. Вызовите `browser_open`.
2. Вызовите `browser_fetch` с URL и нужными параметрами загрузки страницы.
3. При необходимости вызовите `browser_actions`, чтобы взаимодействовать со страницей или дождаться содержимого.
4. Вызовите `browser_screenshot` с ID сессии.
5. По завершении вызовите `close_session`.

Например, аргументы для снимка всей страницы:

```json
{
  "session_id": "my-session",
  "full_page": true
}
```

Параметр `timeout` этого инструмента теперь ограничивает время создания снимка. Инструмент не загружает страницу. Для снимка элемента используйте `selector` или `ref` и не задавайте `full_page=true`.

Снимки экрана по-прежнему возвращают блоки изображения и текста. Текстовый блок содержит URL текущей страницы. Они не возвращают `ResponseModel` загрузки.

Полные схемы приведены в [руководстве MCP](ai/mcp-server.md) и [справочнике API](api-reference/mcp-server.md).

## Пауки и HTTP-запросы {#spiders-and-http-requests}

### Передавайте данные запроса заново при переходе по ссылке {#pass-request-data-again-when-following-a-link}

`response.follow()` больше не копирует `method`, `params`, `data`, `json`, `files` или `multipart` из предыдущего запроса. Он также удаляет унаследованные заголовки `Content-Length` из `headers` и `extra_headers`.

Переход по ссылке теперь начинается с обычного GET-запроса, если данные запроса не переданы явно. Другие общие настройки, например сессия, прокси и обработчики, по-прежнему следуют существующим правилам наследования.

Если старый код зависел от унаследованных POST-данных, замените:

```python
yield response.follow("/next")
```

на:

```python
yield response.follow("/next", method="POST", json={"page": 2})
```

Также явно передавайте `params`, если они нужны следующему запросу. Позвольте HTTP-клиенту вычислить новый `Content-Length`.

### Проверьте отпечатки запросов и сохранённое состояние обхода {#check-request-fingerprints-and-saved-crawl-state}

Отпечаток запроса служит ключом для поиска повторных запросов и ответов в кэше. Теперь его входные данные обрабатываются иначе в трёх случаях:

- `params` объединяются с URL до создания ключа. Запросы к одному URL с разными параметрами строки запроса больше не считаются дубликатами по умолчанию.
- JSON-тела, такие как `{}`, `[]`, `false`, `0` и `""`, сохраняются в ключе. Их ключ больше не совпадает с ключом запроса без тела. `None` по-прежнему означает отсутствие JSON-тела.
- При `fp_include_headers=True` изменение только порядка добавления заголовков больше не меняет ключ.

Если ваш обход использует эти данные, завершите его до обновления или начните новый обход с новой контрольной точкой и новым каталогом кэша ответов. Старые сохранённые ключи могут отличаться от новых. Это изменение идентичности запроса, а не новый формат файла контрольной точки.

Режим разработки теперь записывает ответы в кэш только после проверки на блокировку. Страницы блокировки не сохраняются в кэше как успешные результаты. Существующие файлы кэша не очищаются автоматически. Удалите устаревшие записи, если ранее сохраняли страницу проверки.

Неудачные обходы теперь сохраняют файлы контрольных точек. Проверьте код очистки, если он предполагал, что эти файлы исчезают после ошибки. См. [Пауза и возобновление](spiders/advanced.md#pause-resume) и [Режим разработки](spiders/advanced.md#development-mode).

### Проверьте ошибки robots.txt {#check-robotstxt-failures}

При `robots_txt_obey=True` исключение во время загрузки robots.txt или ответ, отличный от HTTP 200 или 4xx, теперь блокирует запросы к этому домену. Раньше такие ошибки разрешали обход. HTTP 200 по-прежнему предоставляет правила, а HTTP 4xx разрешает доступ.

Результат хранится в кэше на протяжении всего обхода. Исправьте проблему доступа к robots.txt и начните новый обход. Последующие запросы в том же обходе не повторяют неудачную загрузку. Значение по умолчанию `robots_txt_obey=False` не меняется.

### Проверьте ограничения ссылок и обработчики карт сайта {#check-link-restrictions-and-sitemap-callbacks}

- Ограничение `LinkExtractor`, которое ничего не находит, теперь не возвращает ссылки. Оно больше не переключается на всю страницу. Исправьте выражение `restrict_css` или `restrict_xpath`, если обход стал находить меньше ссылок.
- Ограничение теперь может выбрать сам элемент ссылки, а не только родительский элемент. Это может добавить ссылки, которые раньше пропускались. Проверьте ожидаемые наборы URL.
- `SitemapSpider` теперь передаёт URL страниц в `parse()`, если правил нет или у подходящего правила задано `callback=None`. Эти HTML-страницы больше не возвращаются в парсер карты сайта. Реализуйте `parse()` для таких случаев и удалите обходные решения для прежней маршрутизации.
- Начальная метка порядка байтов Unicode удаляется из robots.txt и CSV-каналов. Первая директива robots теперь действует, а заголовок первого столбца CSV больше не начинается с `\ufeff`. Если заданы собственные `headers`, метка удаляется из значения первого поля. Обновите код, который обходил этот невидимый префикс. XML-комментарии и инструкции обработки в картах сайта тоже пропускаются, а не вызывают ошибку разбора.

### Проверьте данные форм, заголовки и JSON в CLI {#check-form-data-headers-and-cli-json}

В данных формы, переданных словарём, значения списков и кортежей теперь разворачиваются в повторяющиеся ключи. Например, `data={"tag": ["a", "b"]}` отправляет `tag=a&tag=b`. Пустой список не отправляет ни одной записи для этого ключа. Если вы не задали заголовок Content-Type, добавляется значение по умолчанию `Content-Type: application/x-www-form-urlencoded`.

Если нужен другой формат передачи, передайте явно закодированную строку или байты. `json`, необработанный `content` и загрузки multipart сохраняют собственную обработку тела. Значения `None` **не удаляются** из данных форм и параметров строки запроса. Они остаются строкой `None`.

HTTP-заголовки отдельного запроса теперь заменяют заголовки сессии независимо от регистра букв. Заголовок запроса `authorization` заменяет `Authorization` сессии, а не отправляется вместе с ним. Удалите код, который обходил повторяющиеся имена заголовков.

Значения JSON в CLI `{}`, `[]`, `false`, `0` и `""` теперь отправляются, а не отбрасываются без уведомления. Кроме того, `curl2fetcher()` теперь применяет User-Agent из параметра curl `-A` и правильно передаёт прокси из `-x` как строку URL. Явный заголовок curl `-H 'User-Agent: ...'` по-прежнему имеет приоритет над `-A`.

## Другие изменения вывода, которые нужно проверить {#other-output-changes-to-check}

Эти исправления не удаляют API, но могут изменить сохранённые результаты и тесты на точное совпадение вывода:

- Сгенерированные селекторы CSS и XPath теперь включают `:nth-of-type(1)` или `[1]`, когда это нужно для выбора первого из нескольких элементов с общим родителем и одинаковым тегом. Обновите ожидаемые строки селекторов. Не удаляйте новую отметку позиции.
- Очищенное содержимое для ИИ теперь сохраняет видимые элементы со значениями вроде `opacity:0.95`, удаляет элементы, скрытые большим числом вариантов встроенных стилей, и элементы `<slot hidden>`. Оно также удаляет все подходящие лишние теги, даже вложенные. Перепроверьте точный вывод Markdown, текста и очищенного HTML.
- Преобразование браузерных ответов теперь читает объявления charset с другим регистром букв, пробелами или значениями в кавычках, например `text/plain; CHARSET = "iso-8859-15"`. Ответы не в формате HTML с такими заголовками теперь используют объявленную кодировку, а не UTF-8 в качестве запасного варианта. Перепроверьте текст, декодированный из этих ответов.

## Проверьте обновление {#verify-your-upgrade}

Запустите небольшой обход перед полной задачей. Проверьте извлечённые данные, посещённые по ссылкам URL, отправленные тела запросов, кодировку сохранённых файлов и поведение кэша или контрольных точек, на которое вы полагаетесь. Для интеграций MCP сверьте входные данные инструментов и возвращаемые данные с текущими схемами.

Изменения прежних выпусков описаны в [истории изменений](changelog.md).
